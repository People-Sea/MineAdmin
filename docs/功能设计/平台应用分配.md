# 平台应用分配

## 1. 功能目标
平台应用分配用于把平台统一持有的腾讯广告第三方应用分配给指定租户，作为该租户发起广告主账号授权的前置条件。

MVP 目标：

- 平台可以把一个或多个应用分配给租户
- 租户只能使用已分配且可用的应用发起授权
- 平台可以停用某个分配关系

## 2. 适用范围
本功能仅平台账号可操作。

租户侧只能使用分配结果，不能直接修改分配关系。

## 3. 关键业务规则
### 3.1 分配前提
应用要能被分配，必须满足：

- 平台应用存在
- 平台应用 `status = enabled`
- 平台应用当前未被标记为明确不可用

### 3.2 分配关系状态
`tenant_app_assignment` 建议只保留简单状态：

- `enabled`
- `disabled`

说明：

- 停用分配关系后，不影响历史授权记录
- 停用分配关系后，租户不能再基于该应用发起新的授权

### 3.3 一个租户可分配多个应用
当前允许一个租户分配多个平台应用。

原因：

- 后续可能存在不同权限范围的应用
- 某个应用失效时，租户仍可切换到其他可用应用

但 MVP 页面上不要求做复杂优先级编排，只需保证：

- 能看到当前已分配列表
- 能新增分配
- 能停用分配

### 3.4 默认使用规则
当前租户侧发起授权时：

- 若只有一个可用分配应用，直接使用该应用
- 若有多个可用分配应用，先按平台设定的默认规则返回一个默认值，页面允许后续再扩展为选择

MVP 阶段优先保持简单，不先做复杂“租户自己选应用”交互。

## 4. 页面与交互
### 4.1 页面入口
平台后台新增：

- `平台管理`
  - `平台应用分配`

也可作为 `平台应用管理` 页内的“分配到租户”动作弹窗实现。

当前优先推荐独立页面，便于后续按租户检索。

### 4.2 列表字段
建议展示：

- 租户名称
- 应用名称
- `app_id`
- 分配状态
- 分配时间
- 最近更新时间

### 4.3 操作项
- 新增分配
- 停用分配
- 启用分配

当前不做：

- 复杂优先级拖拽
- 自动切换主应用

## 5. 数据与状态
### 5.1 依赖表
使用现有 `tenant_app_assignment` 表。

### 5.2 约束规则
- 同一租户与同一平台应用，只允许存在一条有效关系
- 重复分配时，应走恢复 / 更新，而不是重复插入多条启用记录

## 6. 接口与后端实现约束
### 6.1 平台接口
需要提供：

- 分配列表
- 新增分配
- 启用 / 停用分配
- 按租户获取可分配应用候选

### 6.2 租户侧消费接口
租户授权广告主账号前，后端需要先查询：

- 当前租户是否有可用分配应用
- 当前可用分配应用列表
- 默认采用哪一个应用

### 6.3 错误口径
租户侧发起授权时，需明确区分以下提示：

- 未分配应用
- 已分配但全部停用
- 已分配但当前无可用应用

## 7. 验收口径
- 平台能为租户分配平台应用
- 平台能停用某个分配关系
- 租户未分配应用时不能发起授权
- 租户只会使用已分配且可用的应用发起授权
- 停用分配关系后，历史授权记录仍可保留查询
