# 平台应用管理

## 1. 功能目标
平台应用管理用于维护平台统一持有的腾讯广告第三方应用配置，作为后续租户授权广告主账号的唯一应用来源。

当前目标不是做开放平台全量管理，而是先支持：

- 新增平台应用
- 编辑平台应用
- 启用 / 停用平台应用
- 查看应用可用状态
- 记录最近一次校验结果

## 2. 适用范围
本功能仅平台账号可见。

租户侧不允许：

- 新增平台应用
- 修改 `app_id`
- 修改应用密钥
- 修改回调地址

## 3. 关键业务规则
### 3.1 应用存在不等于可用
腾讯广告第三方应用可能出现“配置存在，但当前不可用”的情况。

当前必须按以下口径处理：

- 已创建，但接口权限未开通
- 已创建，但授权回调配置错误
- 已创建，但最近授权 / 换 token 失败
- 已创建，但平台人工停用
- 已创建，但腾讯侧能力异常或权限被回收

因此平台应用不能只维护“有 / 没有”，必须维护“可用状态”。

### 3.2 当前状态口径
建议应用状态拆为两层：

- `status`
  - 表示本平台是否允许继续使用
  - 枚举：
    - `enabled`
    - `disabled`
- `availability_status`
  - 表示最近一次校验结果
  - 枚举：
    - `unknown`
    - `available`
    - `unavailable`
    - `partial`

说明：

- `enabled + unavailable` 是允许存在的组合，表示平台未手动停用，但当前校验失败
- 租户发起授权时，必须同时满足：
  - `status = enabled`
  - `availability_status in (available, partial)`

### 3.3 回调地址规则
- 平台应用必须配置系统当前使用的 OAuth 回调地址
- 回调地址由平台统一维护
- 租户侧不允许覆盖回调地址

### 3.4 密钥管理规则
- 应用密钥必须加密存储
- 页面默认不回显完整明文
- 非必要场景不返回明文给前端

## 4. 页面与交互
### 4.1 页面入口
平台后台新增：

- `平台管理`
  - `平台应用管理`

### 4.2 列表字段
列表页建议展示：

- 应用名称
- `app_id`
- 回调地址
- 平台状态
- 可用状态
- 最近校验时间
- 最近错误摘要
- 更新时间

### 4.3 表单字段
新增 / 编辑表单建议包含：

- 应用名称
- `app_id`
- `app_secret`
- 回调地址
- 备注
- 平台状态

### 4.4 操作项
列表页操作建议包括：

- 新增
- 编辑
- 启用
- 停用
- 触发校验

当前阶段不做：

- 删除物理记录
- 多版本应用管理
- 复杂审批流

## 5. 数据与状态
### 5.1 依赖表
使用现有 `platform_app` 表。

### 5.2 建议补充字段
如当前迁移未覆盖，后续补齐：

- `status`
- `availability_status`
- `last_check_at`
- `last_error_code`
- `last_error_message`
- `secret_ciphertext`

### 5.3 最近错误摘要口径
最近错误摘要只保存当前最近一次失败原因，不做历史堆叠。

历史操作与校验过程统一进入日志系统，不在主表堆历史字段。

## 6. 接口与后端实现约束
### 6.1 后端职责
平台应用管理模块负责：

- 基础 CRUD
- 敏感字段加密处理
- 启停状态控制
- 对外提供“可分配应用候选列表”

### 6.2 校验能力边界
当前阶段先做“基础可用性校验”：

- 必填字段完整性校验
- 回调地址格式校验
- 平台启停状态校验
- 最近授权 / token 交换失败状态回写

当前不要求首期做成复杂探活平台。

### 6.3 代码约定
实现时保持简单：

- 管理页、Service、Repository 各司其职
- 不要为了未来多平台接入提前抽象复杂应用中心
- 当前只围绕腾讯广告第三方应用实现

## 7. 验收口径
- 平台能新增应用
- 平台能编辑应用
- 平台能停用应用
- 列表能展示应用当前可用状态
- 停用应用后，租户侧不能继续拿它发起授权
- 应用不可用时，租户侧能看到明确失败提示
